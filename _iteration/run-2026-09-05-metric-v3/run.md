## 二、做法

### 两处改法（全文与算法在 `fidelity_metric_v3.py` 模块 docstring）

- **分母**：线像素的走向不再从 3x3 模糊后的 Sobel 取，改为对二值线稿在半径 `ORIENTATION_WINDOW_RADIUS_PX` 的圆窗内
  对线像素坐标做 PCA（等价结构张量），主轴＝切向、法向＝切向转 90°，与结果侧 Sobel 梯度方向同一口径（都是数组坐标、
  y 向下；合成 0° / 90° 直线的法向分别为 90° / 0°，逐像素误差 0）。只有窗内各向同性（孤立点、正十字中心）才无定义。
- **配准**：在 ±24 px（`REGISTRATION_SEARCH_RADIUS_PX`，任务给定，覆盖记录里量到的 6–22 px）的整数平移网格上穷举
  49×49 个位移，取最高分；分母固定为原位全部有定义线像素，挪出画幅算未命中；等分取离原点最近的。**分数与位移一起返回**：
  `score`（配准后）、`score_at_origin`（原位，只含分母改法）、`offset_px`（线稿要挪的 (dx 右, dy 下)）、`scale_xy`。
- 三个量分常量 `EDGE_STRENGTH_PERCENTILE = 90` / `TOLERANCE_PX = 2` / `ANGLE_TOLERANCE_DEG = 4` 从 v2 原样 import，不定新值。
  结果侧的降采样 / Sobel / NMS / 百分位阈值逐字复用 v2 的函数——v3 对 v2 的差别只来自两处改法。

### 缩放配准（追加验证；脚本 `缩放配准.py`）

## 四、结论（只写数据支持的）

**1. 分母：三份线稿进分母占比 0.518 / 0.654 / 0.883 → 1.000。** 正竖直线段从 9% / 10% / 52% 进分母变成全进。代价是走向的来源换了：
v2 在斜线上的"走向"其实是台阶不对称留下的残差（完美 45° 线经 3x3 模糊后 Sobel 恰为 0），v3 在两者都有定义的像素上与 v2 的角度差中位 9–13°，
只有 26% 在 4° 内——这不是 v3 偏了，合成直线上 v3 的误差 p90 ≤ 3.0°（半径 5）。

**2. 判据：室内 8 张的"间隙 / 极差"从 0.105 变成 1.079，是变好。** 拆开看：只改分母 0.105 → 0.213（间隙 +0.023 → +0.105，但正确配对自身极差
也从 0.217 涨到 0.496——分母大了、分数散得更开）；再加配准 0.213 → 1.079（极差压回 0.240，间隙涨到 +0.259）。正确配对最低 0.4618 对错配最高 0.2033，
比值 2.27（v2 1.45）。转 90° 配准后仍 ≤ 0.031。揭顶 4 张的比值从 56 降到 21——v3 让三 seed 之间散开了（极差 0.004 → 0.018），间隙照涨（+0.227 → +0.372），
揭顶本来就分得开，这个变化不影响判断。

**3. 窗口半径定 5，依据两头都有数。** 走向误差要压在 4° 角度容差里：半径 3 的 p90 是 10°–11.5°，半径 4 对 2 px 线 5.0° 仍超，5 是两种线宽都进 4° 的最小值
（2.4° / 3.0°）。真跑样本的判据随半径同向：0.40 / 0.78 / 0.95 / 1.08 / 1.16，5 → 6 的增量在小数点后第二位，而距拐角 ≤ 半径的像素占比一直在涨。
6 比 5 高 0.08，这个差别在 8 张样本上不构成改选的理由，也不排除。

**4. 位移：尺子报出来了，没吞。** 室内 8 张里 3 张 |位移| ≥ 4 px（-6、+4、+20），5 张 ≤ 2 px；揭顶与几何基线全在 0–1 px——位移是室内出图特有的。
位移搜索"找得回"：15 / 16 完全相等，唯一的差错是 ±24 搜索边界（-26 超界）。**配准会把错配也抬高**（错配 max 0.084 → 0.203），
且错配的最优位移 5 / 8 贴在搜索边界上；正确配对没有一张贴边界——这是"位移贴边界"可以当疑点看的依据，只是样本少。

**5. 各向异性缩放不解释这批错位。** 最优缩放散在 1 的两侧：室内 8 张 sx 四张 > 1（1.004–1.008）、四张 < 1（0.990–0.996），中位 1.000；sx/sy 中位 1.0000，
落在假设值 1.0046 附近（1.004–1.006）的 4 张，落在 ≤ 1.000 的 4 张。残余平移没有显著变小：客厅-nofurn-seed3 的 20 px 变 17 px，客厅-nofurn-seed2 反而从 0 变 4 px。
噪声底：三份 geometry 自量根本没经过任何缩放（1280×960 原生渲染），缩放搜索照样选出 ±0.004 并多得 +0.0005 至 +0.0036——
所以出图上 ±0.004 的最优缩放与 ≤ +0.03 的增益分不出是缩放还是搜索本身的余量。揭顶 4 张（同样 1168×880）两张精确 (1, 1)、两张增益 ≤ 0.009，
若非等比缩放是系统性的，揭顶不该看不见它。唯一超出噪声底的是主卧-nofurn-seed3（sx 0.990 贴缩放边界、+0.052）与主卧-default-seed1（sx 1.006、+0.039），
方向相反，不是同一个系统性缩放。

## 五、没做的与限制

- 错配对照仍只有"同相机换房间"（室内）与"跨视角"（揭顶）两种；门禁真正要抓的"同房间、墙挪了"没有真跑样本（自证记录 A1 0 / 16），不编。
  阈值因此不定。
- 8 张室内、两间房。窗口半径 5 是在这 12 张 + 合成直线上选的。
- 配准只搜整数平移（默认）；缩放搜索是验证旋钮，生产默认关着，开了耗时按候选组合数成倍涨（121 组 ≈ 10 min / 张）。旋转小角度没搜。
- 缩放验证的平移窗是局部 ±6，不是全幅；表里没有一张最优贴在平移窗边上，但主卧-nofurn-seed3 贴在缩放候选边界 0.990 上，0.990 以下没搜。
- 拐角像素的走向落在对角线上（模块 docstring 限制 4），没剔——剔了就是动分母口径；占比在表四第二段。
- 拼图 `montage-叠线命中.png` 每格标题过长、右端被相邻格盖住，数字以表一、表二为准。
- import-linter 的层契约（`pyproject.toml`）没把 `fidelity_metric_v3` 列进去——任务限定只加新文件；v3 若被采纳，契约要把它与
  `fidelity_metric` 并列为同层兄弟，并把它加进 `image_gateway` / `image_store` 的禁入列表。

## 六、执行者判断，不是裁决

v3 **可以作为室内视角门禁的量分器候选**，依据是 §四 1、2、4 的数：分母含了竖线（1.000），"间隙 / 极差"从 0.105 到 1.079，正确配对最低 0.46 对错配最高 0.20，
转 90° ≤ 0.03，位移找得回。三件事要用户拍、不是尺子能定的：

1. **整图错位算不算几何错。** 算：用 `score_at_origin`（只改分母，比值 0.213 / 2.25——比 v2 好、但不到分得开），并把 |位移| ≥ 某个像素数当不合格；
   不算：用配准后的 `score`（1.079 / 2.27）。两个数 v3 都报，不用重跑。
2. **阈值。** 没有"同房间墙挪了"的真跑样本，任何阈值都是在 8 张、两间房上定的；能说的只是这 8 张正确配对 ≥ 0.46、错配 ≤ 0.21。
3. **位移贴 ±24 边界要不要当疑点。** 错配 5 / 8 贴边、正确 0 / 8 贴边，样本少，只报现象。

缩放假设（§四 5）按这批数不成立，不建议把缩放搜索开进生产路径。
